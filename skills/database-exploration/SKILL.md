# Database Exploration

## 目标

从陌生数据库中定位与用户问题相关的数据，理解其业务含义和粒度，并取得经过验证、可供分析的数据。交付内容应让后续分析者知道数据来自哪里、如何查询、代表什么以及有哪些限制。

## 适用条件

- 用户想了解数据库中的表、字段、数据类型或表之间的关系。
- 用户提出了分析目标，但还没有确定数据来源或查询结果。
- 需要根据业务口径编写 SQL 并获得原始或聚合数据。
- 查询失败、返回空结果、重复行异常或指标明显不合理，需要检查数据来源和查询逻辑。

如果用户已经提供足够的数据且不需要访问数据库，优先使用 `data-analysis`。如果现有分析只需整理成可交付报告，优先使用 `report-generation`。

## 职责边界

本 Skill 负责数据发现、Schema 理解、关系验证、只读查询和结果检查。它不负责对结果进行完整的统计洞察分析，也不负责正式报告排版或数据库性能调优。

Skill 只描述工作方法，不执行数据库操作。只有当前会话实际提供了相应数据库 Tools 时，才能调用它们。若没有表发现、Schema 查询或只读 SQL Tool，必须明确说明当前无法直接访问数据库，并请用户提供 Schema、查询结果或数据文件；不得声称查询已经执行。

## 工作原则

1. 先理解表的业务含义和数据粒度，再生成正式查询。
2. 不根据表名、字段名或常见行业习惯臆测业务定义。
3. 字段名相同不代表可以直接关联；关系必须通过键约束、样本或查询结果验证。
4. 只执行读取数据的 SQL。禁止 INSERT、UPDATE、DELETE、MERGE、CREATE、ALTER、DROP、TRUNCATE 及其他修改数据或结构的语句。
5. 不编造表结构、字段含义、SQL 执行状态或查询结果。
6. SQL 成功执行不等于结果正确；必须检查粒度、过滤条件、关联行数和指标范围。
7. SQL 性能优化不是本 Skill 的核心，但应避免没有必要的全表明细读取和无边界结果集。
8. 对不确定的业务口径或关系明确标注为待确认，不把推测写成事实。

## 工作流程

### 1. 明确要取得的数据

把用户问题转成可查询的数据需求，确认分析对象、指标、维度、时间范围、所需粒度和业务口径。对“收入”“活跃用户”“新增客户”等含义不唯一且会改变查询结果的术语，先确认定义；其他细节可以先采用明确标注的合理假设推进。

### 2. 发现候选数据源

使用可用的 Schema 或元数据 Tool 查看数据库、Schema、表和视图。根据名称、注释和用户目标筛选候选表，不要在没有必要时读取所有表的全部样本数据。说明候选表可能承担的业务作用，并将其与已经确认的事实区分开。

### 3. 理解结构和粒度

检查候选表的字段名称、类型、注释、可空性、主键、唯一键、外键、时间字段、状态字段及指标字段。判断一行数据代表什么实体或事件，例如一笔订单、一条订单明细、一个客户或一日汇总。粒度不清楚时，不要直接 JOIN 或汇总。

### 4. 验证表关系

优先使用明确的外键和唯一约束。没有约束时，将相似字段关系视为候选，并验证数据类型、空值、唯一性、匹配率和关联基数。比较 JOIN 前后的行数，检查是否因一对多或多对多关系造成行数膨胀。无法验证时，明确标注为推测关系。

### 5. 制定查询方案

执行前先列明：数据表及用途、关联条件、过滤范围、指标口径、去重规则、聚合粒度和输出字段。优先明确列出字段，避免 `SELECT *`。使用合理的时间过滤和结果行数限制；若用户确实需要全量结果，应先确认工具的安全范围和数据规模。

### 6. 分步查询并验证

根据可用工具分步完成：先查看少量样本和关键字段取值，再验证过滤条件与关联关系，最后执行完整查询。检查返回行数、时间范围、空值、重复记录、单位、数量级和聚合前后粒度。对于关键汇总，尽可能用基础计数或另一种聚合方式交叉核对。

### 7. 排查失败或异常

- 表或字段不存在：重新读取 Schema，不猜测替代名称。
- 语法错误：依据实际数据库方言修正 SQL。
- 权限不足：说明受限对象，不尝试绕过权限。
- 空结果：检查时间范围、状态筛选、JOIN 和空值处理。
- 行数或指标异常：检查关联基数、重复键、单位和聚合逻辑。
- 超时或结果过大：缩小时间范围、减少字段或分阶段查询；不要以提高风险的方式绕过限制。

每次调整查询时说明要修正的问题；没有重新执行就不能声称结果已经验证。

## 输出要求

探索结束时，根据任务需要提供：

- 用户的数据需求和已采用的口径。
- 相关表、关键字段及各自的数据粒度。
- 已验证的表关系；未验证关系单独标注。
- 实际执行的只读 SQL 和真实返回结果，或明确说明没有执行。
- 对结果进行过的检查及发现的异常。
- 数据范围、缺失字段和其他限制。
- 可交给 `data-analysis` 的字段、粒度、口径和数据质量说明。

仅询问 Schema 时，不必强行编写查询。查询数据不足以支持目标时，指出具体缺少的表、字段、时间范围或业务定义。

## 质量检查

- 已说明数据来源和每行代表的业务对象。
- JOIN 关系和聚合粒度经过验证，或明确标为未验证。
- 查询只读，范围和返回量合理。
- 已检查过滤条件、空结果、重复和异常数量级。
- 区分了实际观察、业务假设和未知信息。
- 没有伪造数据库访问、执行状态或查询结果。
