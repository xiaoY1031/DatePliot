# Report Generation

## 目标

将已经取得并分析的数据转化为结构清楚、证据充分、易于阅读并能支持下一步决策的 Markdown 报告。报告应突出重要信息，同时保留足以正确理解结论的数据口径和限制。

## 适用条件

- 用户要求撰写、完善或整理正式分析报告。
- 已有分析结果、指标和结论，需要面向业务人员或管理者交付。
- 多个发现、表格或图表需要组织成统一叙事。
- 用户提供了分析材料，需要压缩冗余并提高表达清晰度。

只有原始数据、尚未完成分析时，使用 `data-analysis`。还需要从数据库取数时，可按需加载 `database-exploration`。已有材料足够时，不必为了完整流程加载其他 Skill。

## 职责边界

本 Skill 负责结果组织、解释表达、图表规划和 Markdown 报告写作，不负责寻找数据库、重新计算全部指标或验证不存在的数据。Markdown 正文可以直接生成；实际图表、文件导出或报告保存只有在当前会话有对应 Tool 时才能执行。

如果没有图表 Tool，可以提供图表建议或基于真实数据制作 Markdown 表格，但不得声称已生成图像。如果没有报告导出 Tool，只输出报告正文，不声称已保存文件。

## 工作原则

1. 每项关键结论都必须能追溯到输入数据或已完成的分析结果。
2. 不为填满报告章节而编造数字、原因、图表或建议依据。
3. 优先呈现与读者决策相关的信息，执行摘要先给结果，不按分析操作顺序流水账式叙述。
4. 明确区分事实、解释、假设和建议。
5. 指标必须有时间范围、单位、对比基准和必要口径。
6. 图表用于回答具体问题，不能误导或重复正文。
7. 建议必须关联分析发现；证据不足时建议进一步验证，而不是承诺收益。
8. 明确保留数据质量、样本和方法限制，不把相关关系写成因果结论。

## 工作流程

### 1. 确认报告对象和目的

确认报告要回答的问题、目标读者、读者需要做出的决策、详细程度和格式要求。面向管理者时优先呈现影响和行动；面向分析人员时可保留更多方法、口径和质量细节。

### 2. 审核已有材料

整理分析目标、来源、范围、指标定义、数据质量说明、核心数字、发现、图表数据、限制和已有建议。若关键结论没有证据或数字互相矛盾，不补造内容；指出缺失并请求补充，或加载 `data-analysis` 重新核验。

### 3. 建立报告主线

围绕用户问题组织材料：分析了什么、数据表明什么、最重要的变化或差异是什么、其业务影响是什么、建议采取什么行动、结论有哪些限制。只保留支持主线的指标和图表。

### 4. 选择报告结构

根据任务复杂度取舍章节。完整报告可包含：标题、执行摘要、目标与范围、数据与方法、关键指标、核心发现、分项分析、建议、风险与限制、后续分析和附录。小任务不必强行填满每个章节。

### 5. 撰写执行摘要

用简洁段落或要点说明分析问题、最重要的两到五项发现、业务含义、建议行动和主要限制。摘要中的数字必须与正文一致，不能引入正文没有证据支持的新结论。

### 6. 呈现指标和发现

关键指标注明数值、单位、时间范围、对比基准和变化幅度。每项发现使用能表达实际结果的标题，并组织其证据、解释、影响和限制。若基数很小，明确提醒百分比可能放大观感。

### 7. 规划图表和表格

- 时间变化通常使用折线图。
- 类别比较通常使用条形图。
- 构成及其变化可使用堆叠条形图或面积图。
- 分布可使用直方图或箱线图。
- 两个数值变量的关系可使用散点图。
- 精确数值查阅使用表格。

每个图表说明标题、指标、维度、时间、单位、筛选条件和要表达的发现。避免类别过多的饼图、截断坐标误导、缺少单位或把不可比较的指标放在同一尺度。只有实际有数据和图表 Tool 时才输出已生成图表，否则将其标为建议图表或规格。

### 8. 撰写业务建议

每条建议说明要采取的行动、关联的分析证据、适用范围、优先级和后续观察指标。建议应与发现直接对应。无法确定原因时，优先建议补充分析或验证假设；不承诺没有数据支持的收益。

### 9. 保留限制并校验一致性

写明数据范围、完整性、口径、缺失、样本量和无法确认的原因。输出前核对摘要与正文数字、百分比与绝对值、时间和单位、图表与表格口径，以及建议和证据之间的关系。

## Markdown 输出建议

```markdown
# 报告标题

> 分析目的、数据范围与时间范围

## 执行摘要
## 分析目标与口径
## 关键指标
## 核心发现
## 分项分析
## 业务建议
## 风险与限制
## 后续分析
```

按实际任务增删章节，避免重复正文和堆砌指标。

## 输出要求

交付 Markdown 报告正文。重要结论排序清楚，数字可核对，图表在有工具时真实生成、无工具时明确标注为建议。数据不足或存在未验证假设时，在报告中直说，不用空泛文字掩盖。

## 质量检查

- 报告结构服务于目标读者和具体问题。
- 执行摘要与正文一致，关键数字均有来源。
- 指标口径、单位和时间范围明确。
- 图表适合问题且不造成误读。
- 建议与发现有明确证据链。
- 事实、解释、假设和建议没有混为一谈。
- 明确记录限制，没有伪造数据、工具执行或导出状态。
