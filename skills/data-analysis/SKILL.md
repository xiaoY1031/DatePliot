# Data Analysis

## 目标

基于实际数据回答用户的分析问题，识别有业务意义的趋势、差异、结构、异常和潜在问题。分析不止复述数值，还要说明发现为何重要、证据支持到什么程度，以及仍有哪些未知。

## 适用条件

- 用户提供了数据、查询结果或可访问的数据集。
- 需要分析趋势、对比、构成、分布、异常或指标变化。
- 需要先判断数据质量是否会影响结论。
- 已有初步指标，希望继续下钻并解释其业务含义。

只有数据库结构、尚无数据时，先使用 `database-exploration`。已有结论只需整理成正式材料时，使用 `report-generation`。

## 职责边界

本 Skill 负责数据质量评估、分析方法选择、指标计算、结果解释和洞察形成。不负责在陌生数据库中自行寻找数据，也不负责正式报告的完整排版。它不提供统计计算能力本身：计算、清洗或绘图必须依靠当前会话实际提供的 Tools。

如果没有计算 Tool，只有在用户提供的数据足够小、计算步骤可直接核验时，才进行透明的手工计算；应展示公式或中间值。对于大数据、复杂统计或无法核验的计算，说明限制并请求计算结果或可用工具。不得伪造精确统计值。

## 工作原则

1. 先定义分析问题和指标口径，再选择方法。
2. 先评估数据质量，再计算和解释。
3. 每个重要结论都要能追溯到数字、样本范围和计算口径。
4. 比较变化时同时考虑绝对量和相对比例，并检查基数和样本量。
5. 均值可能被偏态或极端值影响；必要时同时查看中位数和分位数。
6. 相关关系不是因果关系；没有因果设计或额外证据时，不宣称某因素导致结果。
7. 缺失值、重复值和异常值不得静默删除或填补，处理方法和影响必须说明。
8. 数据不足时降低结论强度，明确说明不支持哪些判断。
9. 不为了得到显眼结论而忽略反例或与预期不符的数据。

## 工作流程

### 1. 明确分析问题

确认用户要解释的现象、比较对象、时间范围、核心指标，以及结果用于描述、诊断还是决策。把宽泛目标拆成可检验的问题。例如“销售表现如何”可以拆成销售额和订单量趋势、主要贡献维度、下滑或增长发生的时间，以及客单价或购买量的变化。

### 2. 确认数据和口径

记录数据来源、时间范围、每行数据的粒度、指标定义、过滤条件、单位、币种和时区。确认数据是明细、抽样还是汇总。若来源间口径不同，不直接拼接或比较；先说明差异并选择可比范围。

### 3. 检查数据质量

按目标检查：完整性、唯一性、有效性、一致性和异常值。具体检查总行数、关键字段缺失比例、时间断档、主键重复、数值和日期范围、类别编码、单位、业务约束以及异常是否集中于某些群体。

仅凭数值大或小不能判定错误。异常值可单独分析，不能擅自删掉。

### 4. 决定数据处理方式

根据检查结果选择保留、标记、排除、去重、分组处理或适当填补。对关键指标，缺少业务依据时不填补。说明处理规则、涉及记录数、选择理由，以及处理前后结果是否改变。必要时并列展示处理前后的分析结果。

### 5. 建立基础画像

根据任务计算数据规模和时间跨度、核心指标总量、均值、中位数、范围、必要分位数、主要类别数量与占比。基础画像用于发现口径或数据问题，不应把每个汇总值都称为洞察。

### 6. 按问题选择方法

- **趋势分析**：观察方向、环比或同比、拐点及周期性；检查时间断档和口径变化，并按相关维度下钻变化来源。
- **对比分析**：比较绝对差异和相对变化；检查样本规模、基准值、群体构成和比较条件是否一致。
- **分布分析**：查看中位数、分位数、偏态、离散程度和长尾；分布偏斜时不只用均值代表典型情况。
- **构成分析**：分析占比、贡献者、集中度及构成随时间的变化；区分总量变化和组成变化。
- **异常分析**：定位突增、突降或离群点，再检查时间、群体、数据质量和可能事件。异常只是值得调查的信号，不自动证明原因。
- **下钻分析**：仅在总体发现需要解释时，按时间、地区、产品、客户、渠道或其他相关维度逐层拆解。

选择与目标相称的方法；没有统计基础时，不使用复杂方法制造精确感。

### 7. 形成有证据的发现

每项重要发现至少说明观察事实、数字证据、时间与对象范围、业务含义和局限。说明分母、基准和单位，特别是百分比变化。将内容区分为事实、解释、假设和建议，不得把解释或假设写成已确认因果关系。

### 8. 结束与交接

保留与用户目标直接相关、影响较大且证据充分的发现。交给 `report-generation` 时提供分析目标、数据范围和口径、数据质量处理、关键发现与数字、建议图表及字段、限制和待验证假设。

## 输出要求

根据任务规模提供分析目标、数据范围与口径、质量检查、分析方法、关键指标、发现及证据、异常或问题、结论限制和待验证问题。若没有执行计算，应清楚标明这是方法建议或定性观察，而非已计算结果。

## 质量检查

- 分析回答了用户提出的问题，而非只输出通用汇总。
- 已检查数据质量和样本范围。
- 处理缺失、重复或异常的规则透明。
- 变化结论同时考虑了绝对量、比例和基数。
- 每项核心发现都有可核验的证据和口径。
- 区分事实、解释、假设与建议。
- 没有夸大因果关系、编造计算或隐藏不确定性。
